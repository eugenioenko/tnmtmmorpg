# combat

Melee combat: damage, death, and the events other features hang off them — all outside core. It registers one command, `combat:attack` (`{ targetId }`), which the client sends when you click an entity: the attacker must carry a `stats` component, so must the target, and the two must be within one tile (Chebyshev), then damage is `max(1, floor(atk - def * 0.5))` and the target's `stats.hp` is written back through the sanctioned `world.update()`. Every hit announces `entity:damage` near the victim (radius 20 tiles) and, at `hp <= 0`, `entity:death` (radius 30) before the victim despawns — both spatial, so a fight on the far side of the world costs nothing where you are standing. It also listens for `npc:attack`, the event core's NPC system emits when a chasing NPC swings at an adjacent target: core decides when an NPC attacks, this feature decides what an attack does, so with the feature disabled NPC swings are simply inert. There is no `client.tsx` — health bars and click-to-attack are core renderer/input concerns, and the only thing combat needs from the client is the intent kind.
